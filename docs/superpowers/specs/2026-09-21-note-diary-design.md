# 수첩(Note) 양면 다이어리 개편 설계

작성일: 2026-09-21

## 1. 배경과 목표

지금 수첩은 종이색 상자 하나에 메모를 전부 이어붙인 **텍스트 덩어리 하나**를 스크롤시키는 화면이다
(`NotePanelUI.cs`). 항목이 버튼이 아니라 글자라서 "골라서 자세히 본다"가 불가능하고, 메모가 쌓일수록
읽을 수 없는 벽이 된다.

이것을 **양면 다이어리**로 바꾼다. 왼쪽 가장자리에 성격별 세로 탭을 두고, 왼쪽 페이지에 목록,
오른쪽 페이지에 고른 메모의 본문을 펼친다.

## 2. 결정 사항과 근거

| 결정 | 내용 | 근거 |
|---|---|---|
| 탭 기준 | 장소가 아니라 **성격**(증거/증언 등) | 장소(챕터)는 조사 화면이 늘 때마다 자동으로 늘어나므로 탭이 넘친다 |
| 계층 | 3단: **탭 → 챕터 묶음 → 메모** | 성격으로 나누되 "언제 어디서 얻었는지" 맥락을 잃지 않는다 |
| 그림 | **쓰지 않음**. 제목 + 본문 텍스트만 | UI용 아트 에셋이 프로젝트에 하나도 없다 |
| 제목 | 자동 유추 + `Title` 칸으로 덮어쓰기 | 기존 32줄을 손대지 않고도 바로 동작한다 |
| 구조 | 3층 분리 | 규칙과 화면이 섞이면 `NotePanelUI`가 `InventoryPanelUI`(706줄)처럼 불어난다 |
| 세이브 버그 | 이번 작업에 **포함해서 고침** | 개편 후 "사건 경과" 탭이 통째로 비는 형태로 더 크게 드러난다 |

## 3. 고치는 기존 버그

**게임을 껐다 켜고 이어하기 하면 자동 생성 메모가 전부 사라진다.**

- 세이브에는 `SaveData.noteEntryIds`(문자열 목록)만 저장된다.
- 자동 메모의 *정의*(본문·챕터)는 `NoteManager.AddAutoEntry()`가 **런타임에만** `allEntries`에 넣으며,
  CSV에는 존재하지 않는다.
- 불러오면 `recordedEntryIds`에 `auto_BG_01_MyDesk_...` 같은 id가 복원되지만 정의가 없어서
  `GetRecordedEntriesSorted()`가 **조용히 버린다**.
- 같은 세션 안에서 불러오면 메모리에 정의가 남아 있어 멀쩡해 보이고, 껐다 켜야 드러난다.

수첩 내용의 다수가 자동 메모인 설계라 타격이 크다.

## 4. 데이터 모델

`Assets/Resources/Dialogues/NoteEntries.csv` 헤더에 2칸을 추가한다. **둘 다 비우면 자동으로 채워진다.**

| 칸 | 용도 |
|---|---|
| `Category` | `사건경과` / `증거` / `증언` / `업무수첩`. 비우면 자동 유추 |
| `Title` | 목록에 뜰 짧은 제목. 비우면 자동 유추 |

**기존 32줄은 한 글자도 고치지 않는다.** `CSVReader`가 헤더와 값 중 짧은 쪽에 맞춰 읽고
(`for (j = 0; j < header.Length && j < values.Length; j++)`), 없는 칸은 `GetField()`가 빈 문자열로
돌려주기 때문이다.

## 5. 구조 (3층)

| 층 | 파일 | 책임 | 규모 |
|---|---|---|---|
| 보관 | `Assets/Scripts/UI/NoteManager.cs` (수정) | 메모 담기·추가·세이브/복원. 분류는 모른다 | 371 → 약 420줄 |
| 규칙 | `Assets/Scripts/UI/NoteCatalog.cs` (신규) | 카테고리·제목 판정, 탭 목록 정의 | 약 130줄 |
| 화면 | `Assets/Scripts/UI/NotePanelUI.cs` (재작성) | 양면 레이아웃 그리기 | 321 → 약 460줄 |

`NoteCatalog`는 `MonoBehaviour`가 아닌 순수 클래스로 만든다. 입력을 넣으면 답이 나오는 규칙 덩어리라
화면과 분리해두면 나중에 탭을 추가하거나 규칙을 고칠 때 UI를 건드리지 않는다.

`NoteEntry`에 `speaker`, `itemId` 두 필드를 추가한다. 자동 메모가 분류 근거를 들고 있게 하기 위해서다.

## 6. 분류·제목 규칙

### 6.1 탭 4개

| 탭 | 들어갈 것 (현재 데이터 기준) |
|---|---|
| 사건경과 | `Investigate` 5줄 + 현장 관찰 2줄 + **런타임 자동 메모 대부분** |
| 증거 | `Item` 16줄 |
| 증언 | 화자가 있는 `Hotspot` 2줄 + 화자가 있는 자동 메모 |
| 업무수첩 | `Initial` 7줄 |

### 6.2 카테고리 판정 (위에서부터, 걸리는 즉시 확정)

1. `Category` 칸이 채워져 있으면 그 값
2. `TriggerType == Initial` → **업무수첩**
3. 화자 정보가 있으면 → **증언**
4. 아이템 정보가 있으면 → **증거**
5. 나머지 → **사건경과**

3번과 4번이 말하는 "정보가 있다"의 뜻은 메모 종류마다 다르다. 구현할 때 아래 표를 그대로 따른다.

| 메모 종류 | 3번(증언)에 걸리는 조건 | 4번(증거)에 걸리는 조건 |
|---|---|---|
| 자동 메모 (`auto_`로 시작) | `speaker` 필드가 비어 있지 않음 | `itemId` 필드가 비어 있지 않음 |
| CSV 메모 | `TriggerType == Hotspot` **이고** 본문에 `" : "`가 있음 | `TriggerType == Item` |

- **자동 메모**의 `speaker`·`itemId`는 `AddAutoEntry()`에 인자를 추가해 받는다.
  호출부 `InvestigationController.cs:1234` 주변에 `obj.talkSpeaker`와 `obj.itemId`가 이미 있다.
- **CSV 메모**는 `speaker`·`itemId` 필드가 항상 비어 있다. 위 표의 조건만 쓴다.
  현재 `Hotspot` 4줄이 정확히 2:2로 갈린다 (화자가 있는 2줄 = 증언 / 물건·현장을 본 2줄 = 사건경과).

이 방식이면 `InvestigationData.csv`를 역참조할 필요가 없고, CSV 재분류 작업도 0줄이다.

### 6.3 제목 판정 (위에서부터)

1. `Title` 칸이 채워져 있으면 그 값
2. 본문에 `" : "`가 있으면 **맨 처음 나오는 것 하나만** 기준으로 앞토막을 제목으로 쓰고,
   **뒷토막만 본문으로 남긴다**. 뒷토막에 남은 `" : "`는 본문의 일부로 그대로 둔다
3. `TriggerType == Item`이면 `ItemData.csv`의 `DisplayName`
4. 본문 앞 12자. 본문이 12자보다 길 때만 뒤에 `…`를 붙인다

자동 메모는 `AddAutoEntry()`가 `"{오브젝트이름} : {본문}"` 형태로 만들므로 규칙 2에 항상 걸린다.

제목 판정은 본문을 바꾸므로(규칙 2), 저장은 원본 그대로 하고 **화면에 그릴 때만** 잘라 쓴다.
세이브에 잘린 본문이 들어가면 다시 불러올 때 제목이 사라진다.

## 7. 화면

기준 해상도 1920×1080. UI 아트가 없으므로 지금처럼 색 도형으로 그린다.

```
 ┌탭┐┌──────────────책 1520×880──────────────┐
 │경과││  #01                 │  (화자 이름)    │
 │증거││   · 현장 관찰 A      │  ─────────      │
 │증언││   · 현장 관찰 B      │  (본문 첫 줄)   │
 │수첩││  #02                │  (본문 계속)    │
 └──┘│   · 인물 A ◀선택     │  ...            │
     │   · 인물 B           │  ...            │
     └──────────┬───────────┴─────────────────┘
              접힘선            [닫기]
```

- **탭**: 책 왼쪽 바깥에 세로로 4개(각 150×56). 선택된 탭만 밝게. 기존 `SetButtonActiveVisual` 패턴을 따른다
- **왼쪽 페이지**: 챕터 소제목 + 그 아래 제목 버튼 목록, 세로 스크롤
- **오른쪽 페이지**: 제목(크게) + 구분선 + 본문, 세로 스크롤
- **접힘선**: 가운데 어두운 세로 띠
- 탭을 바꾸면 그 탭의 첫 항목이 자동 선택된다
- 항목이 없는 탭은 "아직 적어둔 것이 없다."

건드리지 않는 것: 퀵바 버튼, `UIManager.ToggleNote()`, 씬의 `NotePanel`(여닫힘 스위치 역할),
토스트 알림(`OnNoteAdded`).

## 8. 세이브 확장

`SaveData`에 자동 메모의 정의를 담을 목록을 추가한다.

- 기존 `noteEntryIds`는 **그대로 둔다** → 예전 세이브 파일도 계속 읽힌다(자동 메모만 비어 있을 뿐)
- 저장할 때 `auto_`로 시작하는 메모의 본문·챕터·화자·아이템·순서를 함께 내보낸다
- 복원할 때 그 정의를 `allEntries`에 다시 등록한 뒤 `recordedEntryIds`를 채운다

`JsonUtility`는 `Dictionary`를 직렬화하지 못하므로 `[Serializable]` 클래스의 `List`로 담는다
(`SaveData.cs`, `InventoryManager.cs`가 쓰는 것과 같은 방식).

## 9. 변경 범위

| 파일 | 변경 |
|---|---|
| `Assets/Scripts/UI/NoteCatalog.cs` | 신규 |
| `Assets/Scripts/UI/NotePanelUI.cs` | 재작성 |
| `Assets/Scripts/UI/NoteManager.cs` | `NoteEntry`에 필드 2개, `AddAutoEntry()` 인자 2개, 자동 메모 내보내기/복원 |
| `Assets/Scripts/Save/SaveData.cs` | 자동 메모 목록 필드 추가 |
| `Assets/Scripts/Save/SavePointManager.cs` | 저장/복원 시 자동 메모 함께 처리 |
| `Assets/Scripts/Dialogue/InvestigationController.cs` | `AddAutoEntry()` 호출에 인자 2개 추가 (1줄) |
| `Assets/Resources/Dialogues/NoteEntries.csv` | 헤더에 `Category`, `Title` 추가 (1줄). **git에 올리지 않는다** |

`Assets/Resources/`는 통째로 `.gitignore` 대상이다. 이 저장소는 공개라서 시나리오·조사 대사가
올라가면 누구나 스토리를 미리 볼 수 있기 때문이고, 그림·소리·CSV는 구글 드라이브로 따로
주고받는다(`.gitignore` 66줄, CLAUDE.md 참고). 그래서 CSV 헤더 변경은 **커밋되지 않고 로컬에
남으며, 팀원에게는 드라이브로 전달해야 한다.**

팀원이 예전 CSV(칸이 없는 것)를 그대로 쓰고 있어도 깨지지 않는다. `CSVReader`가 없는 칸을
빈 문자열로 돌려주고, `NoteCatalog`가 그때 자동 유추로 넘어가기 때문이다.

## 10. 검증 절차

이 프로젝트에는 Unity Test Framework 패키지도 `Assets/Tests`도 없다. **자동 테스트를 쓸 수 없으므로
아래를 수동으로 확인한다.**

1. 새 게임 → 수첩 열기 → 업무수첩 탭에 7줄, 나머지 탭은 비어 있음
2. 첫 조사 화면 조사 → 사건경과 탭에 현장 관찰, 증거 탭에 아이템 메모
3. 인물과 대화 → **증언** 탭에 그 인물의 메모
4. 탭을 바꾸면 오른쪽 페이지가 그 탭의 첫 항목으로 바뀜
5. 세이브 → **게임 종료** → 재실행 → 이어하기 → **자동 메모가 남아 있음** (3장의 버그 수정 확인)
6. 개편 전에 만든 세이브 파일 불러오기 → 오류 없이 열림
7. 가장 긴(300자 이상) 증언 메모를 열어 오른쪽 페이지에서 끝까지 읽힘

## 11. 범위 밖

아래는 이번에 하지 않는다.

- **목록 페이지 넘김** (`< 1 2 3 >`). 한 번 검토했으나 양쪽 스크롤로 되돌렸다. 나중에 재검토한다
- **오른쪽 페이지 사진**. UI 아트가 없어서 뺐다
- **"Review" 버튼** (원본 참고 이미지의 장면 다시보기)
- **조사 완료 체크 표시** (원본의 "Investigated")
- **가방·사진 앨범을 다이어리로 통합**. 수첩 안에서만 분류한다
